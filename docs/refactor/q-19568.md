# Refactor scout report: state.py, config.py, app.py, memory/cgroups, small modules

**Top three:**
- **S1:** state.json is 4.2 MB, and 27% of it is a per-instance list of bash commands that nothing has read since 03531d9.
- **S11:** on Linux, the emergency SIGTERM handler in app.py is overwritten by a second registration, so it never runs.
- **S4:** reloading state does not clear the old records first, so a record deleted on disk comes back.

## Section A: Proposed structure

- **bot/config.py:**
  - Keep knobs, paths, provider/account mutators (`set_provider`, `set_accounts`) and the small helpers.
  - Move the prompt blocks (32 blocks over 800 chars, 68K of 161K chars) to **bot/prompts.py**, and keep `from bot.prompts import *` re-exports in config so every `config.X` read still works.
  - Gate: S9's constraints must be handled first, or skip the split.
  - Move the import-time `mkdir` side effects (1484-1488) next to the `DATA_DIR` definitions.
- **bot/store/:**
  - `StateStore` stays as the public facade and keeps its method names. Internals split into domain mixins or helper objects:
    - instances and cost
    - repos (dormant, desc)
    - accounts
    - schedules, wakes, watches and nudges
    - chains (meta, kwargs, plan overrides, deferred, entry_sha, phases)
    - merges
    - settings
  - `_load` and `_serialize` are driven by one field table.
  - The TODO.md deferred-item parsing (1903-2054) moves out to `bot/engine` (it writes repo files, not state).
- **bot/app.py:**
  - `run()` builds an `AppContext` dataclass (store, runner, notifier, scheduler, discord_bot, stop_event, start_time).
  - **bot/startup.py:** account validation, store init and orphan cleanup, OOM probe, deploy registration, orphan scans, reboot announcement and resume.
  - **bot/loops.py:** auto_save, cooldown, autonomy, auto_update.
  - **bot/reboot.py:** relaunch helper, coalesced reboot executor, signal handlers.
  - Harness text anchors move with the code (S13).
- **memory.py / cgroups.py:** keep the layout. Drop the harness-only helpers (S17), make the shared int reader public (S18), and use one pid-alive implementation (S19).

## Section B: Findings

**S1. Dead persisted field, 27% of state.json**
- **Where:** `Instance.bash_commands`, written at lifecycle.py:713 and serialized at types.py:388/465.
- **Category:** dead data / size.
- **What and why:**
  - Its last reader was removed in 03531d9 (2026-09-08, which retired the `tool_hygiene` check).
  - It holds 1,128,965 of 4,178,716 bytes.
  - `RunResult.bash_commands` stays live: runner.py:276-290 merges an aborted attempt with its resume, and runner.py:992 shows the last command.
  - Fix: stop copying it onto Instance and drop it on load.
- **Evidence:** grepped bot/ and scripts/ for readers; measured field sizes with a json breakdown.
- **CLAUDE.md rule:** the prompt-review rule "retired check's flags stay readable" concerns eval files, not this field. None directly.
- **Test coverage:** scripts/verify_paths.py:471/496 asserts bash history is not rewritten in state, so that harness must be updated.
- **Risk:** low. **Blast radius:** types, lifecycle, state. **Phase:** 3 (crosses the runner/types slice).

**S2. orch_resume_payloads grows forever**
- **Where:** bot/discord/orchestrator.py:71 and 142-157, stored in platform_state.
- **Category:** unbounded growth.
- **What and why:** 949 entries (590 KB). Entries are only removed when popped, never by age. Each store does a full synchronous `save()`.
- **Fix:** prune entries older than `_WAVE_ABANDON_HOURS` (12h) in the existing autonomy sweep.
- **CLAUDE.md rule:** spawn-wave "late child is still delivered". The prune must exceed the late-delivery window; 12h matches the abandon horizon.
- **Test coverage:** test_orchestrator_join.py.
- **Risk:** low-medium. **Phase:** 3 (discord slice).

**S3. Load and save hand-mirror ~40 fields**
- **Where:** state.py `_load` (215-305) and `_serialize` (337).
- **Category:** duplication / drift risk.
- **What and why:** every persisted field is listed by hand twice. A field table of (key, attr, default factory, codec) gives one source of truth.
- **CLAUDE.md rule:** none.
- **Test coverage:** indirect through many harnesses; there is no dedicated round-trip test, so add one first.
- **Risk:** medium. **Blast radius:** state.py only. **Phase:** 2.

**S4. Reload resurrects deleted records**
- **Where:** `reload_if_changed` (state.py:314), called from scheduler.py:99 and app.py:919.
- **Category:** correctness bug.
- **What and why:** it calls `_load()`, which re-adds into `_instances`, `_schedules` and `_watches` without clearing them first. A record deleted in the file survives the reload, while live records are overwritten by the file's values.
- **Evidence:** read `_load`. It only assigns into the dicts; there is no `.clear()` anywhere on that path.
- **CLAUDE.md rule:** none.
- **Test coverage:** none.
- **Risk:** medium. Clearing changes behaviour for unsaved in-memory edits, so decide whether dirty state blocks a reload.
- **Phase:** 2.

**S5. Synchronous full rewrites on the event loop**
- **Where:** state.py `_write_payload` (385), `save` (411), and auto_save_loop at app.py:793.
- **Category:** efficiency.
- **What and why:**
  - Every `save()` is a full 4 MB compact dump on the event loop.
  - With backup on, it also `shutil.copy2`s the 4 MB file to .bak every 60s.
  - Inside state.py there are 56 `self.save()` calls vs 15 `mark_dirty()`, and about 70 `.save()` calls repo-wide.
  - Measured: `json.dumps` takes ~10 ms plus `to_dict`.
- **Fix:**
  - (a) S1 and S2 cut the payload about 40%, which is the cheapest win.
  - (b) Rotate the .bak with `os.replace` of the previous file instead of copying 4 MB.
  - (c) Convert non-critical `save()` calls to `mark_dirty()`, one domain at a time.
- **CLAUDE.md rule:** repo_desc says "miss path defers via mark_dirty, state.json is megabytes". That is consistent with this.
- **Test coverage:** partial.
- **Risk:** for (c), crash-loss windows. Keep `save()` where a crash between write and use matters: wakes, watches, pending merges, session binding.
- **Phase:** 2.

**S9. Split prompts out of config.py**
- **Where:** config.py:~1421 to the end.
- **Category:** file split.
- **What would break:**
  - (a) `prior_art.block_history` defaults to `path="bot/config.py"` and uses a `git log -L /^NAME\b/,...:bot/config.py` range. `-L` history does not follow a move across files.
  - (b) prompt_review.py:130/159 tells the reviewer owners are "constants in bot/config.py".
  - (c) Rejection fingerprints hash `(file, flag)`, and test_prompt_review.py uses `FILE: bot/config.py`, so every existing rejection would stop matching.
  - (d) `eval._ATTRIBUTION` maps flags to names only, so it survives.
- **Mitigation:**
  - `block_history` takes a list of paths: `-L` on the new file, and `-G\bNAME\b -- bot/config.py` for history before the move.
  - The fingerprint normalises config.py and prompts.py to one key.
  - Update the prompt_review wording.
- **CLAUDE.md rules:** "prompt review: rejection remembered by target", "block's own edit history". Preserved only with the mitigation. Treat as report-only unless the mitigation ships in the same change.
- **Test coverage:** test_prompt_review.py, test_prior_art.py.
- **Risk:** medium. **Phase:** 3.

## Section D: Rejected because deliberate

- **`cgroups.scope_status`:** a test seam, used at test_session_cgroups.py:215 and 590.
- **`paths.reset_for_test` and `procutil.request_stop`:** a test seam, and an API used by the botctl CLI.
- **`_read_limit` "max is -1" semantics:** documented as distinct.
- **Separate PSI readers for memory, CPU and IO:** "each PSI signal keeps its own reader".
- **`_probe_scope` uses `subprocess.run`:** "a diagnostic gets its own subprocess seam".
- **`adopt_session` runs as its own task:** the harness enforces that it is not awaited inline.
- **No supervisor kill path:** "supervisor footprint is a recorder".
- **The `own_cgroup` parameter rather than new readers:** documented, because of the import-cycle direction.
- **`check_weights` reads the cgroup files directly:** deliberate.
- **Unique scope unit names per spawn:** deliberate.
- **memes.py keeps its own env read (42-47):** the config setting it used was once erased by a merge.
- **meeting_watch's own `_pid_alive`:** a Windows tasklist variant in a script outside the bot package.
- **scripts/instances.py's own `_pid_alive`:** it must not import bot.config.
- **`list_repos()` unfiltered:** deliberate, so any store split must keep it.
- **Mutable config globals rewritten by `set_provider`/`set_accounts`:** safe, because consumers read them as `config.X`. Only `OPENAI_API_KEY` (audio.py) and `REPOS_BASE_DIR` (commands.py:2696, read inside a function) are imported by name, and neither is mutated after startup.
