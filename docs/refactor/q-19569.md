# Section C: Import graph and layering

AST scan of bot/: 88 modules, 344 module-level edges, 432 function-level import sites.

**Leaves hold.** textutil, procutil and paths import nothing from bot. bot.platform does not import bot.engine or bot.discord, so it is correctly upstream of engine.

**Cycles (strongly connected groups of modules):**
1. **config and claude.provider.** config.py:129 imports `get_provider` at module level, and provider imports parser, which imports config. config.py:743 also imports claude.types inside a function to avoid a cycle.
2. **engine.commands, eval, lifecycle, workflows.** Only commands:24 and workflows:23 import at module level. The cycle closes through function-level imports at lifecycle:505, :790, :1228, workflows:816, :1000, :2848, and eval:474-542.
3. **discord.bot, fleet, interactions, slash_commands.** bot:42-44 imports at module level. The reverse edges are either `TYPE_CHECKING` (fleet:46, interactions:26, slash_commands:32) or function-level (fleet:424, interactions:731, :782).

**Function-level imports by file:** interactions 61, app 59, wizard 43, commands 36, discord/bot 25, runner 22. Most are startup-cost deferrals rather than cycle dodges. The cross-layer ones are listed in X15.

**Violations:** the cross-layer imports in X15, plus engine.memes:122 importing the discord library inside a function. bot.monitor importing discord is by design: it is a Discord-only service.
