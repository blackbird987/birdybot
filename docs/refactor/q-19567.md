# Scout report: bot/discord + bot/platform

**Headline:**
- **Two real bugs.** The two "stop all" buttons kill sessions the wrong way, which produces red FAILED cards, can start account failover, and leaves the channel lock held. The /new repo picker will crash once a 26th repo is registered.
- **Why bot.py regrew:** five features landed inline in the bot class. Nothing gave them anywhere else to go.
- **Platform abstraction:** keep the Messenger protocol, because the test fakes are a real second adapter. Delete the leftover Telegram code.

## Section A: structure and verdict

**What regrew in bot.py** (847 lines at 898d4c1, now 2693). Net lines added:
- **Usage gate and queue: about 420 lines** (deb261f +250, ffabc07 +89, 8a722bf +117).
- **Attachment and image ingest: about 500 lines** (8eaf8cf +206, 914ca3a +108, df71ad6, c84475c, f073fca, 43cad14). About 350 of them are module-level helpers, the rest sits inline in on_message.
- **Spawn and orchestrator closures inside `_ctx`: about 240 lines** (5231e95, 6f90d82, fff1d4d, d53b5ed).
- **Guest lockdown: +88** (5397075).
- **Worktree and release recovery: +117** (af024a6, b235f35).
- **Reboot resume +60** (64043b8), **lobby clean +68** (101dd0f).

**Root cause:** `ClaudeBot` is the service locator. Every module reaches into its private attributes (`bot._store` 111 times, `bot._forums` 98, `bot._is_owner` 57), so a new feature lands where the state lives.

**Proposed layout:**
- **`discord/attachments.py`:** the helpers plus on_message's ingest, returning `(text, image_paths, problems)`.
- **`discord/usage_gate.py`:** a `UsageGate` class with a public API. interactions.py currently calls `bot._usage_queue_*` privates.
- **`discord/thread_ctx.py`:** the `_ctx` factory, attaching session callbacks by default, with an explicit `attach=False` for chain and prompt-review steps (CLAUDE.md says those must not bind). Add `async with thread_turn(ctx)` for the post-run bookkeeping, which is copied 9 times.
- **`discord/spawn_ctx.py`** (or orchestrator.py): the spawn, notify-parent, reply-to-child and wave closures.
- **`discord/startup.py`:** on_ready recovery, worktree cleanup, recovery-event surfacing.
- **`discord/deploy_flow.py`:** the roughly 500-line deploy cluster now in interactions.py.
- **Rule for new code:**
  - A new button is a handler module registered with `@button("name")` in a dispatch table.
  - A new slash command is a thin wrapper over the engine, behind a guard decorator.
  - `ClaudeBot` keeps only Discord event wiring.
  - Write this rule into CLAUDE.md so it is enforced.

**Platform verdict:**
- **Messenger protocol: keep.** There is one production adapter, but about 12 test fakes implement it, so the seam is real.
- **Telegram residue: delete.** That covers the `platform` fields, the per-platform dict in the notification service and its unused unregister, the dead non-Discord branch in the engine, "None on Telegram" comments, and probably `markdown_to_markup`, which the Discord adapter implements as identity.
- **Fix the leaks** where engine code reaches into Discord: add a near-limit hook on the Messenger, and move the bash allow/deny lists out of `discord/access`.

## Section B: findings

**D1. `interactions.py:1026` and `wizard.py:180`: stop-all kills sessions the wrong way**
- **Category:** correctness bug, inside a duplicate.
- **What:** both stop-all handlers call bare `bot._runner.kill(inst.id)`, which is a non-intentional kill. Per CLAUDE.md that renders red FAILED cards, matches the account-failover signature, and leaves the channel lock held.
- **Fix:** both should go through `perform_kill` / `kill_and_wait(reason="kill")` in one shared helper.
- **Evidence:** came in with 76ab86b and 2779d55. The runner's kill docstring (runner.py:5785) describes the same failure.
- **CLAUDE.md rule:** "Interrupting a session". The fix enforces it.
- **Coverage:** none. test_kill_shape does not reach stop-all.
- **Risk:** low. **Phase:** 1.

**D2. `slash_commands.py` cmd_new (~492-550): picker has no 25-button cap**
- **Category:** latent crash.
- **What:** one button per pickable repo, all in one View. 22 repos are registered and none hidden, so the 26th repo makes /new throw.
- **Fix:** paginate, or switch to a select menu.
- **CLAUDE.md rule:** "truncate, don't crash" (Discord limits).
- **Coverage:** none. **Phase:** 1.

**D3. `bot.py` on_message (2043, 446 lines, complexity 77)**
