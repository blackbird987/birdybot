# Runner slice scout report (runner.py, parser.py, types.py, session_index.py)

**Bottom line:** most of runner.py's bulk is stateless git, worktree, session-file and prompt code sitting on the class. Moving it out is low-risk if the test seams are handled. The real complexity is in three places: the recovery chain in the main run function (complexity 163), the stream reader (110) and the merge function (76). Those want decomposing in place, keeping the order of the recovery steps exactly as it is. I found only one dead function.

## Section A: Proposed split

Turn `bot/claude/runner.py` into a package `bot/claude/runner/`. `__init__.py` re-exports every name imported today: `ClaudeRunner`, `RebootResult`, `SESSION_STRIPPED_ENV_VARS`, `_NOWND`, `_SIGNAL_EXIT_CODES`, `is_kill_shape`, `_no_productive_work`, `_lifetime_kill_result`, `git_fail_reason`, `version_tags`, `missing_predecessor_release`, `orphaned_releases` and the merge-fail constants. Leaves never import `core` or `__init__`. Leaves may import config, procutil, gitpaths, parser, types, memory and cgroups.

Import graph afterwards: `core` → {accounts, admission, reaping, prompt_build, session_files, worktrees, git_merge} → git_release. `git_merge` → worktrees (it removes a worktree on merge) → git_release (tag helpers). No cycles. The existing lazy `bot.engine` imports stay lazy.

**Seam rules. These are the risky part, and Phase 1 must settle them before anything else moves:**
1. **Methods stay as methods on `ClaudeRunner`.** Tests assign instance attributes such as `runner._stream_output = fake` (10 sites), `_pick_account`, `_ensure_worktree`, `_await_memory_headroom` and `_hydrate_cache`. Tests also build `ClaudeRunner.__new__` without running `__init__` (verify_hydrate_same_account:42, verify_restore_stash:76/119/149, test_cooldown_early_retry:98, test_worktree_recovery_git:110). So **use mixins, not composed sub-objects.** For example, `class ClaudeRunner(AccountsMixin, AdmissionMixin, SessionFilesMixin, PromptMixin, WorktreeMixin, MergeMixin)`. A sub-object created in `__init__` would not exist under `__new__`.
2. **Rebinding a module global silently stops working once the code using it moves.** `runner_mod.unusable_reason` (15 uses in 4 tests) feeds the accounts code. `runner_mod.run_capture` and `runner_mod.tempfile.mkdtemp` feed worktree recovery. `runner_mod._OOM_JOURNAL_LAG_SECS` feeds the OOM classifier. After a move these patches still succeed but patch nothing, and the tests stay green while blind. **Fix: retarget each patch to the new module in the same commit.** Add a harness guard that fails if `bot.claude.runner.<name>` is patched for a name that `core` does not read.
3. `patch("bot.claude.runner.config.CLAUDE_ACCOUNTS")` keeps working, because config is a shared module object.

## Section B: Findings

**R1** runner.py ~16 sites | duplication | The same "if there is a progress callback, try it, log the exception" block is repeated about 16 times. Replace it with `_notify(on_progress, h, d, what)`. Evidence: grep for `log.exception("Progress callback error`. Rule: none. Tests: the failover, overflow, thrash and oom harnesses capture progress text. Risk: low. Phase 1.

**R2** runner.py 3612-3626, 3674-3687, 3797-3815 | duplication | Three "Switching to backup account" blocks (cooldown, notify, re-enter on the next account). Replace them with `_failover_to(next_acct, reason, ...)` that calls the existing `_reenter`. Rules: model limit must stay above usage limit, and the account step must stay below `killed_intentionally`. The helper only removes the duplication and keeps the order. Tests: test_account_failover, test_model_limit_failover, test_failover_session. Risk: medium. Phase 2.

**R3** runner.py 3098-3110 and 3518-3531 | duplication | Two copies of the "conversation lost, announce once" block (`on_recovery` plus `warning_posted`): dead-session Layer 3 and the fresh run after a context overflow. Merge into `_announce_session_loss`. Tests: test_dead_session_recovery, test_context_overflow. Risk: low. Phase 2.

**R4** runner.py 2653-3859 | complexity | The main run function is 1207 lines with complexity 163. Split it into setup (`_prepare_spawn`: account pick and refuse-to-spawn 2722-2784, pre-emptive downgrade 2793-2820, env strip, hydrate, scope wrap), then `_spawn_and_stream`, then an ordered list of recovery steps. Each step is a method taking the result and recovery state and returning a result or None. Keep the `_reenter` closure semantics by passing a bound reenter. Rules touched: rung order (the killed-intentionally return first; the OOM classifier before the reaps; context overflow standing down on fatal auth; model limit before usage limit; failover last), "lifecycle.run_instance does not bind", and the wording "lifetime limit" and "killed by the system's out-of-memory protection". All are preserved if the list is a literal tuple in today's order. **Add a harness test that asserts the order.** Tests: 9 harnesses cover the recovery steps. Risk: high. Blast radius: one function. Phase 3.

**R5** runner.py 3900-4759 | complexity | The stream reader is 860 lines with complexity 110, and its stall-check closure (3971-4321) carries 9 nonlocals. Extract a `_Watchdog` class holding a state dataclass, with `tick()` covering the lifetime, memory guard, fleet arbitration and stall branches. Rules touched, all to be preserved:
- The session is told before `proc.terminate()`.
- The reap stand-downs (a completed `result` event, intentional kills) stay above the reap returns.
- `_bot_signalled` is marked before any signal is sent.
- `WATCHDOG_TICK_SECS` stays the poll cadence.

Tests: test_runner_watchdog, test_lifetime_cap, test_memory_guard, test_kill_shape. Note test_memory_guard reads `runner_mod._memory_kill_result`, `_fleet_kill_detail` and similar, so re-export them. Risk: high. Phase 3.

## Section C: Cross-slice notes

- **The rest of the code reaches into runner internals.** Counts of private attribute uses outside runner.py: `_account_cooldowns` 35, `_stream_output` 22, `_set_account_cooldown` 12, `_store` 11, `_tag_release_at` 8, `_last_merge_failure_kind` 8, `_intentional_kills` 8, `_active_tasks` 8, `_model_cooldowns` 6, `_auth_cooldowns` 6. Many are in engine/commands and discord/interactions and wizard. The accounts mixin should expose public read accessors, so the commands scout's slice can switch to them. The test uses can stay private.
- **Shared types live in the wrong package.** `Watch`, `Schedule`, `ChainPhaseState` and `Phase` live in `bot/claude/types.py` but belong to engine and store. Moving them needs state.json round-trip tests and re-exports. Coordinate with the engine and store scout.
- **The path encoder sits in the wrong layer.** `bot/engine/session_fork.encode_project_path` is the canonical encoder, yet bot/claude imports it lazily from engine (runner 4744, 6404; session_index 88). Moving it to `bot/claude/session_files.py` and re-exporting it from session_fork fixes the layering without undoing the consolidation.
- **The duplicate Discord kill loop** (interactions vs wizard, from dupes.txt) calls `runner.kill`. Whoever merges those must keep `reason=` and `owns_card` (CLAUDE.md "Interrupting a session").

## Section D: Considered and rejected because they are deliberate

- **The two re-entry closures** (`_reenter`, from 2990b6b, and `_resume_same_conversation`) are already the deduplication. Keep them; R4 only moves the steps around them.
- **The recovery step order** is load-bearing. It is reordered by no finding.
- **The three PSI readers** stay separate ("Each PSI signal keeps its own reader").
- **`adopt_session` stays un-awaited** in the spawn path (`_check_adoption_offpath` fails the suite otherwise). Do not inline it.
- **The scope probe keeps its own subprocess seam** (`_probe_scope` uses `subprocess.run`, not the async API the runner spawns sessions with).
- **Scope unit names stay unique per spawn**, and **`_lower_priority` is not a `preexec_fn`**.
- **The rmtree divergence is intended:** the merge success path falls back to `shutil.rmtree` (7786), while orphan cleanup refuses it (t-3700 docstring, 9359) and discard does not do it. Different policies, report-only.
- **The reap tell-then-terminate order and `_bot_signalled` marked before the signal** both stay. R5 must preserve them.
- **The two error wordings** ("lifetime limit", "killed by the system's out-of-memory protection") must stay verbatim, because the account-failover check matches on them.
- **No sync twin** of any async helper. Do not re-add one during the split.
- **The `encode_project_path` delegates** were kept on purpose by 96ad54f and the other consolidation commits. Only the caller-less one (R11) goes.

No previous attempt to split runner.py turned up: I searched its 209 commits for "split", "extract" and "module". fc2ac1b (retry paths), a4b56d4 and 85bf8f7 (shared `run_capture`) and 8292e88 (removed unreferenced functions) are prior deduplication work that this plan builds on, not something it re-adds.
