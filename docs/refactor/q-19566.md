**Five scouts done. Three live bugs found, plus a plan to split the two oversized engine files (commands and workflows) into about a dozen modules. Nothing was changed.**

The three bugs:
- **Spawned children never report back.** Children run through the normal chat path, and only the background path tells the parent "I finished". In the log, 96 of 110 wave completions were closed by the 5-minute cleanup sweep instead of by the children.
- **Code examples inside a ``` block still fire.** A spawn, reply, chain, repo or image command shown in a code block runs for real. Only wake and watch skip those.
- **Auto-fix picks the oldest run, not the newest.** The list comes back newest first and the code takes the last item.

**A. Proposed layout**
- `commands.py` becomes a thin entry point that re-exports old names, because test scripts import private names.
- New engine modules:
  - `query.py`: the chat run and its "waiting" card
  - `branch_actions.py`: one merge-and-record and one discard, shared by the slash command, the button, the resolver and the chain
  - `resolver.py`
  - `callbacks.py`: a button dispatch table
  - `repo_cmds.py`, `settings_cmds.py`, `admin_cmds.py`
- `directives/` package: `common.py` (one quoted-line check that knows about fences, one key=value parser, one pairer, one notify helper), plus `chain.py`, `spawn.py`, `reply.py`, `repo_cmd.py`, `dispatch.py`.
- Split `workflows.py` into:
  - `steps.py`: the button step handlers
  - `chain.py`: a state object, one function per step, and a dispatch dict
  - `plan_parse.py`, `policy.py`, `spawn.py`, `finders.py`
  - git helpers move into `runner`/`gitpaths`
- Import rule: `directives/*` never imports `commands`, `lifecycle` or `workflows` at module level. `check_budget` and `_get_channel_lock` move to a leaf module.
